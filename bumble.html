Bumble's Hive

A location-based service that helps Bumble users meet authentically in third spaces — with exclusive partner discounts, privacy-first design, and a seamless upgrade path to Premium.

UI/UX Designer & Researcher
Adv. Interaction Design Studio
Three Weeks
Figma, FigJam, Miro

Overview

Hive is a location-based service that helps Bumble users meet one another at third places. By turning on their location, users can find participating Bumble Partner businesses that offer exciting opportunities to meet potential partners authentically — while enjoying the benefits of exclusive discounts for new budding couples.

Note: Exclusive and unlimited access is given to Bumble Premium+ Users.

I utilized data from previously failed Bumble features that involved location-based services. From their shortcomings, I analyzed the data to figure out how to appeal to the Bumble user demographic. I also used the Uber design system to create new features — practicing working with a design system and creating components that fit both the design system and Bumble's aesthetic.

The core problem: how can Bumble create a location-based service that attracts more paying users, motivates those with location on to subscribe, and nudges those without location on to enable it? The flexibility of this feature also means it can easily be adapted to both BFF and Bizz modes.

Design System

Working with Uber's Base

I was given Base — Uber's design system — to work with. The components were fairly sleek and simple, providing good guidance on implementation. The main challenge was adapting a predominantly black-and-white system to fit Bumble's 'bumblebee' yellow aesthetic.

The most challenging part was making new components fit the design theme. I had to reuse icons from Base and build them into new components. For example, to signal a Premium feature, I repurposed a ribbon icon — which carries a different meaning in the Uber app. The limited icon set meant I had to create new icons or cleverly repurpose existing ones.

The most surprising thing I learned about design systems was how structured they are. There are so many components and sub-parts that go into them — it made me value the amount of work that goes into building one. When designing with an established system, the overarching themes are already built in, which actually speeds up the process significantly.

Research

Data-Driven Insights

I first brainstormed ideas around the prompt to:

"Correlate usage frequency, location and social drivers to gain insights about the circumstances that motivate users who experience precise location notifications to convert to subscribers."

From this, I chose an idea centered on having people meet one another "authentically" — where everyone nearby is a Bumble user actively looking to connect with like-minded others.

Analyzing the Data

From the data of two previously failed features, I found that "Map Integration for Nearby Events" outperformed "Proximity Alert" in adoption rates. This influenced me to build on the map integration component to enhance the social aspect of the app — adding discounts and the ability to see nearby users to maintain adoption and retention.

Designers should rely on data to some extent — but data alone only goes so far. Overwhelmingly positive or negative data points signal something clearly, but mixed data (which is the norm) should prompt deeper thinking rather than knee-jerk decisions. This is where creativity, user testing, and intuition fill the gaps.

Pain Points

Before moving into design, I identified five core questions that needed to be answered:

  • How can locations be used to benefit users?
  • How would we make sure all users are safe?
  • What if users don't want to turn on their location?
  • How can we have free users switch to premium?
  • How can we place women first with this feature?

Using Locations to Benefit Users

I incorporated a map feature showing users where Bumble Partner locations are. Within these locations, users can see:

Venue Details
  • Address, rating, and photos of the partner location.
Peak Times
  • The busiest times when most Bumble users gather at that location.
Personalized Tags
  • Tags that align with the user's personal preferences and interests.
Enter Event Button
  • Only available when physically at the venue — unlocking discounts and showing the number of Bumble users present.

Safety & Privacy

How Would We Make Sure All Users Are Safe?

To protect user privacy, I introduced single bee placards. These include a name, age, photo, and icebreaker — but users don't need to use a real photo of themselves. Instead, they can create alternative placards visible only to certain gender categories. Users can also opt out entirely to remain anonymous.

Placard settings live inside the user's regular Bumble profile settings — keeping the experience familiar and frictionless.

Design Decisions

Key Decisions Made

  • Used Uber's Design System: Base as the component foundation.
  • Created a new icon within the navigation bar exclusively for the Hive feature.
  • Added new location-related onboarding questions when users first create their account.
  • Introduced Bumble Partner — a distinct section for businesses who opt in as a Hive location, including an analytics dashboard and discount creation tools.
  • No desktop experience — this is intentionally mobile-only since the feature is location-dependent. This also motivates more in-app usage.
  • Hive is designed to be easily transferable to BFF and Bizz modes without significant redesign.

Reflection

What I Learned

From this project, I learned how to integrate new components and work with existing ones in an already-built design system. If I had more time or resources, I would spend more on micro-interactions in Figma to make the feature flow feel polished and truly native to Bumble.

I would also run user interviews and tests with people outside the design space — most of my critique came from other designers, and I want to know how non-designers would react to the feature.

Going Beyond the Brief

If I had strictly followed the requirements as written, I would have missed several critical design considerations. The brief said nothing about user safety when location is enabled — without addressing this, the feature could have put users at risk of harassment. My solution introduced anonymous placards and opt-out controls to give users safety through choice.

Similarly, the brief didn't address third-party partnerships. I developed the Bumble Partner concept independently — a separate interface for businesses to view analytics and create user discounts — to make the full ecosystem work.
